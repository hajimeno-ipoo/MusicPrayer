# Apple Musicの2倍速入力で歌声の判定値が下がった原因

検証日: 2026-10-18

## 結論

歌声活動量の大きな差の主因は、2倍速の取得経路で高音域が減衰したことだった。時間と音程を元に戻しても、弱くなった高音域は復元されない。その音を既存の解析器へ渡したため、歌声の判定値が低くなった。

通常速度で取得した同じ音声に、実測に合わせた高音域の減衰だけを与えると、2倍速側に近い歌声判定の低下を再現できた。今回の確認は、この入力差と歌声判定の因果を対象にした。2倍速の方式全般の可否や、ビジュアライザーの良否は判定していない。

## 変更内容

- 対象：Wink「愛が止まらない ~Turn it into love~ (Remastered 2018)」、catalog ID `1403236244` の30〜70秒。
- 作業種別：歌声活動量の差だけを対象とする原因調査。
- 変更前：歌声判定が低下することは記録済みだったが、音声のどの違いが原因か不明だった。
- 変更後：高音域の減衰を測定し、その減衰だけを通常速度の音に再現すると、歌声判定も低下することを確認した。
- 内部実装・画面の変化：製品コード、配布アプリ、操作画面の変更なし。
- 影響範囲・戻し方：調査記録だけを追加・追記した。取り消す場合は今回の調査記録を削除し、前の比較記録の追記を戻す。

## 再現と切り分け

検証用アプリごとにmacOSのAudioCapture許可をtccdログで照合し、タップの無音化設定と非ゼロPCMを確認してから取得した。画面収録・画面共有・マイク入力は使っていない。音声はRAMにだけ保持し、ファイルには保存していない。

通常速度と、音程補正OFFの2倍速で同じ短区間を取得した。2倍速側を半分のサンプルレートとして扱い、元の時間・音程へ戻した。両者の対応区間を合わせ、同じ24 kHz・チャンネル数・4096フレーム単位で同じMusicUnderstandingSessionへ渡した。解析項目とMusicAnalyzer.convertも共通である。ローカル用とは別の歌声解析器は作っていない。

最初の短区間測定では、2倍速側→通常速度→同じ2倍速側の順で解析し、2倍速側の結果が再度一致した。正しい48 kHzへの変換、左右の平均を取ったモノラル化、波形の正負反転でも差は消えなかった。これらを今回の低下の主因とする根拠は得られなかった。

## 見つかった音声の差

約8.5 kHzから上で、2倍速側の音が系統的に弱くなっていた。精密比較での代表値は次の通り。これは元の曲の周波数へ戻した後の値である。

| 周波数 | 通常速度に対する2倍速側の差 |
|---|---:|
| 約8.6 kHz | −0.67 dB |
| 約9.1 kHz | −4.13 dB |
| 約9.4 kHz | −8.24 dB |
| 約9.7 kHz | −14.30 dB |
| 約9.95 kHz | 約−23 dB |

前の音程確認で使ったスペクトル相関は、約180 Hz〜2.5 kHzの範囲で計算されていた。音程が戻っていることは確認できたが、この高音域の違いを確認する測定にはなっていなかった。

## 原因を確認する比較

高音域の減衰だけを再現する中央揃えのFIRフィルターを作り、通常速度で取得したRAM音声へ一度だけ適用した。6 kHz以下の振幅を維持し、6 kHzより上には実測された減衰特性を与えた。時間、音程、曲、解析器、解析への渡し方は変更していない。

初回のフィルターは9.95 kHzより上を未測定の外挿で補っていた。そのため精密比較では11.83 kHzまで測定し、その実測に合わせたフィルターを使用した。11.83〜12 kHzだけは外挿であり、録音した音声そのものとは区別している。

| 同じ短区間の入力 | 歌声判定値の平均 |
|---|---:|
| 通常速度の音 | 0.732 |
| 通常速度の音に、実測した高音域の減衰だけを再現 | 0.524 |
| 実際の2倍速取得音を元の時間・音程へ戻したもの | 0.514 |

比較は入力の最初と最後の3秒を除いた約34秒。表の値はAppleの解析器が返す歌声活動量の判定値であり、歌声の物理的な音量や誤り率ではない。高音域を変えるだけで、通常速度と2倍速側の平均値の大きな差をほぼ再現した。処理後の通常速度と実際の2倍速側の時系列の相関は約0.9998、平均絶対差は約0.0095だった。

両入力が完全一致したという結果ではない。残った小差と、WebKit・AVFoundation内部のどの部品が高域減衰を作るかまでは特定していない。ただし、高域減衰を単独で再現して歌声判定の大きな低下を再現したため、今回の主因を音声入力の高域減衰と判断できる。

## 結果と次のアクション

原因調査は完了。製品への修正実装は行っていない。次のアクションはなし（今回の原因調査は完了）。ユーザーの承認・確認は不要。

両方の検証用接続を停止し、再生速度1・音程補正ON・停止状態へ戻した。検証プロセスの終了を確認し、RAM音声を解放した。専用の一時ファイルは削除した。
