# Music Prayer

ローカル音源とApple Musicの曲を再生できるMacプレイヤーです。音に反応する立体リボンと水面反射、カセット、スペクトラム都市を選べます。

## 必要な環境

- macOS 27以降、Xcode 27（Music Understanding、Now Playingを使用）
- Metal対応Mac
- AVFoundationで読み込めるローカル音声ファイル。検証にはMP3、WAVを使用

## 起動

```bash
./script/build_and_run.sh
```

CodexのRunボタンも同じスクリプトを使います。アプリは `dist/MusicPrayer.app` に作成されます。通常は処理速度を最適化したReleaseビルドです。`--verify` は起動確認、`--logs` はログ、`--debug` はDebugビルドとデバッガ、`--build-only` は起動せずビルドします。

曲を追加ボタンまたはドラッグで読み込み、Spaceで再生・一時停止。Command＋左右矢印で前後の曲へ移動します。シークバーはドラッグ中に映像の雰囲気を確認でき、離すと音声が移動します。曲一覧と解析は右上のボタン、出力先は音量の横のスピーカーボタンで開きます。

## Apple Music

「Apple Music」ボタンで曲名・アーティスト・アルバムを検索し、結果の「一覧に追加」を押します。曲はローカル音源と同じ一覧へ登録され、ピンクの「Apple Music」表示で区別できます。追加するだけでは再生中の曲を変えません。一覧から曲を選ぶだけでは再生せず、再生ボタンを押すと始まります。前後の曲・シャッフル・リピートも通常どおり使えます。「ローカルに戻る」といった手動切り替えは不要です。

一覧の順番・Apple Musicの曲情報・選択と再生位置を保存します。従来のローカル音源の一覧も読み込めます。再起動では曲を自動再生しません。配信曲を一覧から外すと、MusicPrayerへの登録と、その曲の保存済み解析結果を削除します。Apple Musicのライブラリは変更しません。

公式画面からも直接登録できます。検索画面の「Apple Musicを開く」から公式画面を開き、追加したい曲を再生して、画面上部の「再生中の曲を一覧に追加」を押してください。一時停止中も追加できます。追加後も公式画面を表示したまま、曲の再生を続けられます。同じ曲は重複登録せず、配信曲として取得できない項目は登録しません。「プレイヤーに戻る」から曲の一覧を開き、登録した曲を選んで再生できます。

公式画面のプレイヤーとMusicPrayerの一覧再生は、別々の接続で動きます。公式画面での選曲・再生・停止・シーク・音量は公式プレイヤーだけに反映され、MusicPrayerのローカル再生や一覧再生を操作しても公式プレイヤーの状態は変わりません。直接登録ボタンは曲情報を一覧へ渡します。検索画面と公式画面は、macOSのライト／ダーク設定に合わせて表示します。公式ページ内のアルバム固有の背景色と文字色は、Apple Musicの配色を使います。

音声の受信・再生は内部のApple Musicエンジンが担当し、ログイン状態はAppleとWebKitが管理します。独自のトークン作成・取得や追加の有料開発者登録は使いません。契約曲のフル再生にはApple Musicの有効な契約が必要で、未サインインではプレビューになります。

取得できたApple Musicの歌詞は、ジャケットと同時に表示します。ローカル歌詞と同じ描画・折返し・フォント設定を使います。語ごとの時刻付き歌詞を優先して取得し、その時刻で色を変えます。語の時刻がない曲は、事前解析に使うメモリ上の音声を小さなブロックでAppleの音声認識へ渡します。配信元の行時刻を保ち、各行の区間で照合できた文字へ認識時刻を付けます。一部の行が認識できなくても、確認できた行の文字時刻は使います。結果は配信曲専用の解析フォルダへ保存し、次回の再生で再利用します。従来の音楽解析だけが保存されている曲は、歌詞の時刻を作るため一度だけ音声を取得します。細かな時刻が取れなかった行も、配信元の時刻で表示し、ローカル解析の歌声活動量に沿って色を進めます。この進行は表示用の推定で、認識した文字時刻とは区別します。音声認識処理自体が失敗した場合は、理由と「解析をやり直す」を表示します。行の時間を文字へ均等に割り振る着色はしません。時刻のない本文は白で表示します。上段の歌詞ボタンは、従来どおりローカル曲へ歌詞を登録するためのボタンです。配信歌詞はローカル曲用の歌詞ファイルには保存しません。

Apple Musicの再生音も、ローカルと共通のビジュアライザーへ渡します。音量・低音・中音・高音・64帯域のスペクトラムに反応し、同じメニューから表示を選べます。Macがシステム音声取得の許可を求めた場合は許可してください。アプリ自体は画面を取得せず、音声の録音保存も行いません。配信音の音量設定分を解析前に補正するため、音量を下げても反応の強さを保ちます。音量0・ミュートでは音自体を取得できないため反応が止まります。一時停止時は音声取得も停止します。

Apple Musicも、再生中の音を既存のMusic Understanding解析へ渡します。右上の「詳しい解析」で音量の記録を確認でき、曲の自然終了後にBPM・拍・小節・キー・楽器の活動量・曲の区間が反映されます。自然終了後の解析結果は、一覧に登録されている曲ごとに保存します。次の再生やアプリ再起動後は保存結果を読み込み、ローカル曲と同じ処理で、拍・楽器・区間などをビジュアライザーへ反映します。停止しても確定済みの解析結果は表示できます。初回の再生中はFFTと逐次届く音量に反応します。

Apple Musicの曲を一覧に追加すると、未解析の曲の事前解析が自動で始まります。曲ごとの独立した処理で、最大2曲を同時に無音で解析します。曲一覧と選択曲のメイン画面では、各曲の進捗バーと％を表示します。準備中と仕上げ中は状態を表示します。完了後、曲一覧には「解析済み」、メイン画面にはローカル曲と同じ区間・BPM・キーを表示します。事前解析では音程を保った2倍速再生から音声を取得し、音の長さを元に戻して既存の解析処理へ渡します。完了した結果は保存して次の再生から使います。保存済みの曲は内部再生を始めず、結果だけを再利用します。

音声取得の準備が遅れた曲も、自然終了までに取得できた区間の解析結果を保存します。取得前の区間や未測定の拍・楽器は作りません。シークやミュートでは異なる位置の音を連結せず、続きの区間を別に解析します。一時停止の時間は解析へ含めません。曲の途中で停止した未完の解析は確定保存せず、次の再生で解析します。

事前解析中もApple Music公式画面を操作できます。公式画面で曲を再生して登録し、プレイヤーへ戻って一覧を確認した後、再び公式画面で次の曲を再生・登録できます。画面移動や次の曲の再生・登録で、先に登録した曲の解析を中断したり、先頭からやり直したりしません。2曲を登録すると、それぞれの解析が同時に進みます。3曲目以降は空いた解析処理から始まります。通常再生と事前解析は音声の処理を分けており、解析する曲が公式画面の再生曲へ混ざらないようにしています。

配信曲でも音量横のメニューから出力先を選べます。Apple MusicではMacの既定出力を変更し、ローカル曲ではこのアプリの出力を変更します。配信曲は再生を始める前や一時停止中にもシークでき、音声の準備前に選んだ位置は次の再生時に反映します。歌詞の取得を含めて公式サイトの構成に依存するため、Apple側の変更時には内部の接続部分の修正が必要になる場合があります。

右上のビジュアライザー選択メニューで「リボン」「カセット」「スペクトラム都市」を切り替えます。リボンでは水面のクリック・ドラッグで反射を揺らせます。

カセットは厚み・窓・リール・ネジを持つ立体モデルです。曲のジャケットと曲名をラベルへ貼り、床の影、経過・残り時間、進行ラインを表示します。再生中はリールが回り、一時停止では止まります。スペクトラムは64帯域FFTだけでなく、拍・小節・BPM・Pace・楽器の活動・音量・曲の区間・キーに反応します。既存の曲解析を共用し、カセット本体の形は変えずに、周囲のスペクトラム・照明・視点が変わります。

スペクトラム都市は、手前方向に8棟、奥行き方向に5棟を置いた、計40棟の街です。音源の64帯域FFTを隣り合う帯域でまとめ、建物の高さへ反映します。金色の光は長く湾曲する7本の細線として描き、小節の進みに沿って位置と高さが変わります。床の鏡像と柔らかな照り、近くのビル下部の暖色も光束へ追従します。実際の音の強さに合わせて光り、無音や一時停止では金色の光とその反射・照りが消えます。拍・小節・ドラムも明るさに反映します。歌声が強まると中央の建物の内側の同色の光が下から満ち、その他の楽器が活発になると屋上が明るくなり、小節に沿って青紫の光が街路を流れます。歌声の光は床の鏡像にも映ります。これらの楽器反応には既存の音楽解析を使います。

建物はシアン・鮮やかな青・紫のクリスタルを表す材質で、細い白い輪郭と淡い照明の反射を持ちます。広い面から床や奥の部品が透けます。内側の色付きの光と表面の反射を別々に描き、黒い床には建物と光の鏡像が映ります。16:9の構図を既存のプレイヤー領域へ、周囲に余白を取り、縦横比を保って収めます。一時停止中は音への反応の余韻が収束すると描画を休止します。

詳しい解析中も再生できます。解析失敗は理由と再試行ボタンを表示します。取得できないBPMやキーは作りません。解析はMac内で行い、音源を外へ送信しません。

## 保存

再生する曲、停止位置、音量は `~/Library/Application Support/com.hazimeno.MusicPrayer/queue.json`、解析は同フォルダの `Analysis/` に保存します。ローカルの解析キャッシュは音源のSHA256とバージョンで照合します。Apple Musicの解析結果は `AppleMusicAnalysis/` に分け、曲ID・長さ・解析バージョンで照合します。曲一覧に残る間は保持し、一覧から最後の登録を外すと削除します。起動時にも一覧にない配信曲の解析ファイルを整理します。音源自体は変更しません。

## 検証

```bash
swift test
```

検証の結果と仕組みは `FOR[hazimeno_ipoo].md` をご覧ください。先に予約した次曲を再生中に変更すると、音声を現在位置から予約し直すため短い途切れが生じる場合があります。描画は60fpsを要求し、実際の回数はディスプレイとGPUの性能に応じます。一時停止中は、表示の余韻と水面の波が十分小さくなった後、同じ画面のGPU描画を省きます。水面の操作、シーク、曲や画面サイズの変更では描画が再開します。
